# 製品マニュアル変換サービス 仕様書

**発注者:** 株式会社ヤマナミ工機（架空）　製品企画部
**版:** 第1版（2026-10-19）
**問い合わせ:** 発注側の担当（研修では講師）

> この仕様書・スキーマ・サンプル XML・既存コードの会社名・製品名は、すべて架空です。

---

## 1. 背景と目的

当社は業務用の電気ケトル「KT-200」シリーズを販売しています。
製品マニュアルは XML で管理していますが、Web で閲覧できる形にするたびに、手作業で HTML を作っています。

このサービスは、**マニュアルの XML を受け取り、内容を検証したうえで、HTML と JSON に変換して返す**ものです。

- HTML は、お客様が Web で閲覧するために使います
- JSON は、当社のサポート用のシステムに取り込むために使います

変換の本体の一部は、以前に別の委託先（有限会社サンプルソフト・架空）が作成しています（`training/app/`）。
今回は、これを引き継いで完成させていただきたいと考えています。

---

## 2. 用語

| 用語 | 意味 |
|---|---|
| マニュアル | 1つの製品の取扱説明書。XML 1ファイルが1冊 |
| 章 | マニュアルの中の区切り。章の中に、さらに章を入れられる |
| 階層 | 章の入れ子の深さ。いちばん外側の章が第1階層 |
| 注意 | 安全に関わる記述。読み飛ばされないようにしたいもの |

---

## 3. 入力（マニュアルの XML）

### 3-1. 全体の構造

```
manual
├── meta
│   ├── productName   製品名
│   ├── modelNumber   型番
│   └── revisionDate  改訂日
└── body
    └── section（1つ以上）
        ├── title     見出し
        ├── para      本文（0個以上）
        ├── caution   注意（0個以上）
        ├── list      箇条書き（0個以上。中は item）
        └── section   下の階層の章（0個以上）
```

- 文字コードは **UTF-8** とします
- 形式の定義は、同じフォルダの `manual.xsd` を参照してください

### 3-2. 必須の項目

**製品名・型番・改訂日は必須です**。1つでも欠けているマニュアルは、変換せずにエラーとします。

### 3-3. 改訂日の形式

**改訂日は `YYYY-MM-DD`（例: `2026-10-19`）とします。**

### 3-4. 章の階層

**章の階層は3階層までとします**。4階層以上のマニュアルはエラーとします。

### 3-5. 見出し

- すべての章に見出し（`title`）が必要です
- **本文の無い章でも、見出しは出力します**（「準備中」の章を作ることがあるため）

---

## 4. 検証

変換の前に、次を確認します。1つでも当てはまれば変換しません。

| # | 確認すること | エラーの内容（例） |
|---:|---|---|
| 1 | XML として正しく読めるか | `XML を読み込めません` |
| 2 | 必須の項目（製品名・型番・改訂日）があるか | `型番がありません` |
| 3 | 改訂日の形式が正しいか | `改訂日の形式が正しくありません: 2026/10/19` |
| 4 | 章の階層が3階層以内か | `章の階層が深すぎます（4階層）: 〇〇` |
| 5 | すべての章に見出しがあるか | `見出しの無い章があります` |

**エラーが複数ある場合は、すべてを一度に返してください。**

---

## 5. 出力

### 5-1. HTML

| 要素 | 出力のしかた |
|---|---|
| 製品名 | ページの見出し（`h1`） |
| 型番・改訂日 | 製品名の下に表で出す |
| 目次 | 型番・改訂日の下に、すべての章の見出しを番号つきで出す |
| 章の見出し | 第1階層を `h2`、第2階層を `h3`、第3階層を `h4` とし、**番号を付ける**（例: `1`、`1.1`、`1.1.1`）。**番号は、同じ階層の中で1から数え直す** |
| 本文 | `p` |
| 注意 | **目立つように表示する** |
| 箇条書き | `ul` と `li` |

- `&` `<` `>` などの記号を含む文字は、**画面にそのまま表示されるように**出力してください（HTML として解釈させない）

### 5-2. JSON

サポート用のシステムに取り込むための形式です。

```json
{
  "productName": "電気ケトル KT-200",
  "modelNumber": "KT-200",
  "revisionDate": "2026-10-19",
  "sections": [
    {
      "number": "1",
      "title": "安全上のご注意",
      "paragraphs": ["……"],
      "cautions": ["……"],
      "lists": [["……", "……"]],
      "sections": []
    }
  ]
}
```

- `sections` は章の入れ子と同じ形にします
- 文字は UTF-8 のまま出力します（`\u` で始まる形にしない）

## 6. 使い方（入口）

### 6-1. コマンド

```
php bin/convert <入力ファイル> [--format=html|json]
```

- `--format` を省略した場合は HTML を出力します
- 結果は標準出力に、エラーは標準エラーに出します

| 終了コード | 意味 |
|---:|---|
| 0 | 変換できた |
| 1 | 検証のエラー（第4章の 2〜5） |
| 2 | 入力のエラー（ファイルが無い・XML として読めない・指定が誤っている） |

### 6-2. HTTP

```
POST /convert?format=html|json
Content-Type: application/xml
（本文にマニュアルの XML）
```

| 状態 | 返すもの |
|---|---|
| 変換できた | `200`。HTML または JSON |
| 検証のエラー | `400`。JSON で `{"errors": ["…", "…"]}` |
| `POST` 以外 | `405` |

- 開発中は `php -S localhost:8000 -t training/app/public` で動かします
